## 3. Scope Boundary & Approved Deferred Items Summary

1. **Family / Guardian Booking (DEFERRED BY APPROVED SCOPE):**
   - **Root Cause:** Schema PK/FK constraint where `PatientProfiles.UserId` is a 1:1 primary/foreign key to `UserAccounts.UserId`. Adding dependents without individual credentials requires schema mutation (`GuardianUserId` column or separate `Dependents` table).
   - **Action:** Formally deferred to post-submission maintenance to preserve the canonical 38 physical table Database First boundary.

2. **Custom Service Workflow Step Versioning Table (DEFERRED BY APPROVED SCOPE):**
   - **Root Cause:** The 38 canonical tables define services and departments, but omit custom physical workflow step versioning tables.
   - **Action:** Workflow configuration is handled cleanly through service parameters and audit logs. Adding physical tables is deferred to post-submission schema evolution.
